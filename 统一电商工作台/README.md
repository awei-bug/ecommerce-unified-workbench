# 电商综合工作台

双击 `启动工作台.bat`，或在本目录运行 `python start.py`，然后访问 `http://127.0.0.1:8090/`。保持启动窗口打开；按 Ctrl+C 停止本次启动的服务。启动器只停止自己创建的进程；所需端口被占用时会退出，不接管已有服务。

工作台通过内嵌页面接入三个现有前端，每个模块仍使用自己的服务、登录和权限。模块保留自己的导航和登录状态；这不是统一账号，也不是将三个前端源码合为一套组件。服务端口就绪只说明端口可访问，不代表数据库、登录或商品同步成功。

“商品协作”是新工作台内的原生页面：使用云购商家账号登录，从列表选择已授权的跨境演示店铺，查看该店铺商品。可刷新店铺列表；授权变更后需要刷新，每次查询商品时后端仍重新校验权限。页面只读；当前登录只适用于这个页面，其他三个模块仍使用各自登录。需要先按[统一账号权限与界面改造说明](../统一账号权限与界面改造.md)配置映射和员工商品查看权限，并在跨境后端显式启用 `MERCHANT_PRODUCT_READ_ENABLED=true`。默认关闭时登录可以成功，但商品查询不可用。

工作台只在本机内存保存商家 token，并通过 HttpOnly、SameSite 会话 cookie 关联浏览器，工作台会话 30 分钟过期、服务重启后失效。退出会清除工作台本地会话，不撤销云购已签发的 token，也不会退出三个旧模块；每次商品查询仍由跨境服务向云购验证身份和当前权限。此方案仅供本机演示，不能用于公网部署。

## 运行前

- 安装 Node.js、Python，以及三个项目各自的依赖和虚拟环境。内容编排器使用当前 `python`，需要安装其 `requirements.txt`；云购和跨境后端分别使用各自的 `.venv`。
- 云购的 `run_dev_api.py` 使用项目现有开发数据库配置；跨境后端使用自己的环境配置；内容项目沿用当前环境的数据库配置。**不会自动迁移或重置数据库**。启用真实模型或已有店铺凭证时，仍需按原项目配置与权限操作。
- 本机 `8120、8110、3100、5174、5000、8080、8000、5175、8090` 端口必须空闲。服务日志写入本目录 `.runtime/`；失败时查看对应日志，修复后重新启动。
- 工作台默认给三个服务设置 `demo` 数据中心租户和本机 token。云购自动同步进程不会自动启动；需要时按 [三系统联调说明](../三个电商系统联调说明.md) 配置并单独启动。真实多租户映射尚未完成。

## 范围

工作台供本机开发和演示，监听 `127.0.0.1`，不是公网部署方案。三个模块独立登录，跨境店铺关联和自动同步仍有演示范围限制。浏览器直接访问子模块时以各模块的页面和服务状态为准；如启动时页面加载失败，可在服务就绪后点击「重新加载」。

可在本目录运行 `python verify.py` 执行隔离浏览器验收；需要本机 Chrome 和跨境前端的 Playwright 依赖。验收使用临时 SQLite 数据库、测试账号和本机进程，不使用现有业务数据库；脚本只在临时库预置测试映射和授权，不会为实际账户创建授权。它会占用上述端口，运行前须确保端口空闲。
