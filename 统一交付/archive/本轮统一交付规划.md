# 本轮统一交付规划（后端统一登录 + 数据库统一）

## 访谈决策基线（用户已确认，2026 本轮）

| 编号 | 决策项 | 结论 |
|---|---|---|
| D1 | 统一身份源 | **云购账号为唯一身份源**：沿用 `t_tenants` / `t_users` / `t_roles` 与云购 RBAC，跨境与内容平台均向云购校验会话 |
| D2 | 数据库统一节奏 | **分期切换 PostgreSQL**：内容平台 + 跨境先归 PostgreSQL；商城保持 MySQL 过渡，schema 对账完成后再切 |
| D3 | 重复模块处置 | **先出「重复能力清单 + 删除建议」**，逐项经用户确认后才删除；本轮不删任何模块 |
| D4 | 前端宿主策略（后续轮实施） | 以云购 Vue3 后台（`/admin/`）为宿主外壳，跨境并入其路由，内容平台 React 先嵌入后逐页迁移 |
| D5 | 本轮交付边界 | **只做后端**：一次云购登录签发会话 + 内容/跨境后端均校验该会话 + 内容与跨境共用 PostgreSQL 并验收。前端入口保持现状 |

## 本轮不在范围内（明确排除，避免误判完成）

- 商城 MySQL → PostgreSQL 的正式切换（需先补齐 5 张未建模表、12 个遗留字段的 schema 对账）。
- 前端源码合并与重写（D4 仅作为后续路线记录）。
- 任何模块的删除（等 D3 清单逐项确认）。
- 公网部署、真实租户隔离证明、真实店铺业务接口授权。

## 任务分解

| 任务 | 负责 | 边界 | 验收标准 |
|---|---|---|---|
| T1 跨境统一登录接入 + PG 迁移 | 子代理 1 | 仅 `跨境电商运营智能辅助系统/backend/` | 业务接口按云购会话校验身份；Alembic 在 PostgreSQL 可升级/回退；SQLite 数据迁移可重入并逐表对账；pytest 通过 |
| T2 内容平台接入统一会话 + PG 固化 | 子代理 2 | 仅 `电商智能内容生成与商品知识平台/apps/api-server/`、`apps/data-hub/` | 关闭 `authMode=off` 后由云购会话驱动身份；项目归属仍按成员角色校验；node --test 129 项通过；`/api/health` 报告 PostgreSQL |
| T3 重复能力清单与删除建议 | 子代理 3 | 只读分析，不改任何代码 | 输出重复能力对照表，每项含证据路径、重叠字段、删除风险、建议动作 |

## 验收环境约束（并行派发，防止互相干扰）

- 固定端口 `5000/8000/8080/8090/5174/5175/3100/8110/8120` **不得占用**；各子代理测试一律用临时端口或进程内测试。
- 数据库测试使用隔离实例/临时库，不写现有业务库；跨境测试用临时 SQLite 或隔离 PG，内容测试用隔离 PG。
- 三任务边界互不重叠：T1/T2 分别只动各自项目，T3 只读。

## 风险与已知限制

1. 跨境后端当前使用固定演示账号与固定令牌，替换为真实会话校验会牵动多个路由，需逐项覆盖读写。
2. 内容平台默认 `off` 本地演示身份；切换到正式鉴权会影响现有 129 项测试的前置身份设定。
3. 商城仍为 MySQL，本轮结束后**三系统并未使用同一种数据库**——这是分期决策的既定中间态，不得对外表述为已完成。
4. 跨系统身份查询与数据库写入之间不是分布式事务，不构成真实租户隔离证明。
