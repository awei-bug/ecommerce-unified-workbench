# 统一登录改造：完成报告

## 用户诉求
「一个登录页面」。改造前实测有 **4 个独立登录页**（云购后台、跨境、内容平台、工作台商品协作），用户明确不接受。

## 核心方案：Cookie 跨端口共享

**关键技术事实（实测验证）**：Cookie 在 `127.0.0.1` 上跨端口共享——在 8080 写入的 cookie，8090/5174/5175 都能读到。

因此采用：
1. 云购后台（`/admin/login`）成为**唯一登录页**
2. 登录时除返回 JSON，同时写 `dsh_merchant_session` cookie（`HttpOnly; Path=/; SameSite=Lax; Max-Age=86400`，无 `Secure`、无 `Domain`）
3. 云购新增 `GET /user/session/`：读 cookie 换身份 + token，失败返回真 HTTP 401
4. 各模块前端读同一 cookie 换会话，**不再有自己的登录页**

## 过程中的两个真实缺陷（我修复的）

1. **`/user/session/` 不返回 token**（子代理漏了）。前端需要 token 调各自后端的 Bearer 接口，只返回身份会导致「会话识别了但业务接口 401」。已补 `'token': _extract_token(allow_cookie=True)`。
2. **启动器未给内容后端注入 `MERCHANT_IDENTITY_URL`**，导致内容 API 返回 `503 IDENTITY_NOT_CONFIGURED`，前端看起来像未登录。已在 `start.py` 补注入。

## 遗留与限制

1. **跨境预览库需 `alembic upgrade head`**：本轮用 `.runtime/cross-preview.db`（已迁移副本）绕过，原库仍停在 `20261015_0017`。
2. **云购演示账号需显式映射**：已在内容库建 `tenant=1/staff=1 → user_demo` 映射；换账号需重新映射（`scripts/link-merchant-account.js`）。
3. **无状态 JWT 无法服务端吊销**：logout 只清浏览器 cookie，已泄露 token 在有效期内仍可用。
4. **视觉仍不统一**：四个模块各自风格（深绿/深蓝/浅紫），这是下一阶段工作。
5. **`shop-web` 曾静默退出**：本轮重启后正常，未根治。
