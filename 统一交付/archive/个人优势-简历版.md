# 个人优势（简历用 · 精简版）

> 一句话定位：**能把多个独立系统收敛成一套可运营的垂直电商平台**——统一身份、统一数据、统一界面，并让每一步都有实测证据。

---

## 领域

垂直电商（多租户 SaaS + 跨境运营 + AI 内容生产）｜全栈：Python / Node / Vue / React / PostgreSQL

---

## 干了什么 · 产出什么

**1. 三系统整合｜4 个登录页 → 1 个**
把云购多租户 SaaS、跨境电商运营、AI 内容平台三套独立系统并成一套。以云购租户/员工 RBAC 为唯一身份源，用同域 Cookie 跨端口共享会话，一次登录贯通三端。
→ 删除各端自有登录页；伪造身份头、失效会话、无账号映射一律拒绝（fail-closed）。

**2. 统一身份与会话治理｜从"能登录"到"能吊销"**
登录签发 HttpOnly 会话 Cookie；各服务实时回源校验租户、角色与动作码，租户与操作人只来自已验证会话，不接受请求体指定。
→ 退出即服务端吊销（jti 落库），已泄露 token 立即失效，不再等过期。

**3. 数据库统一｜内容+跨境迁至 PostgreSQL**
内容平台与 data-hub 切 PostgreSQL；跨境 Alembic 迁移补齐至 head（35 → 38 表、逐表对账）；商城做 PG 兼容审计，识别 5 张未建模表与 12 个遗留字段后再决策。
→ 迁移幂等、可回退、源库只读不破坏；不拿"能连上"当"已迁移"。

**4. AI 内容 → 商品知识 → 商城/跨境链路**
React + Express + FastAPI + LangGraph 构建内容工作流，成功任务的 Listing 标题/正文经 data-hub 同步到商城与跨境。
→ 一条商品贯穿三系统可演示；同步失败可重试、缺价进待补价、同名身份冲突拦截，不覆盖商城库存与售价。

**5. 工程质量｜726 项测试，0 失败**
每个"已完成"都带实测命令与输出，不采信口头结论。
→ 云购 296、跨境 217、内容后端 152、内容前端 50、跨境前端 11；三端构建全通过；本轮改动零乱码零 BOM。

## 三个可讲的判断（面试加分项）

- **同域 Cookie 跨端口共享**做统一登录：比引入 SSO 服务轻，比 iframe 传 token 稳，且天然 fail-closed。
- **"名字像"不等于"是重复"**：跨境 `automation_rules` 与云购 `t_automation_rules` 逐字段比对后确认语义不同，避免了误删；对 27 个能力域出了重复清单与删除前置条件。
- **配色统一要做对比度核算**：靛紫换青绿后品牌色作文字仅 3.74:1，新增 `--brand-text` 提到 5.47:1，白字按钮渐变端从 2.49:1 提到 5.47:1。

## 事实边界（写进简历也要能答得出来）

- 全部为本地多服务联调与隔离数据库验证，**无真实商户规模、营收或性能提升数据**，故不写。
- 跨境发布链路只做到内容核对与绑定，**未接真实平台授权与自动发布**。
- 商城仍用 MySQL 过渡，**三系统尚未同库**；前端仍以 iframe 聚合，路由级合并是后续工作。
- 生产级租户隔离、跨系统分布式事务**未做**，不宣称具备。
