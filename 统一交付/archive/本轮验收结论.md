## 二、调度者独立复现的关键证据

### 一次登录打通两个系统（真实云购 token，非桩）

跨境 `/api/v1/auth/me` 实测返回：
```json
{"id":"staff-1-1","name":"店长","role_name":"超级管理员",
 "organization_id":"org-demo-001",
 "permissions":["category:write","order:cancel","order:complete","order:create", ...]}
```
- `id` 与 `role_name` 来自云购会话
- `organization_id` 来自租户→组织映射，**不接受请求体指定**
- `permissions` 是云购真实动作码

内容平台同 token：`GET /api/projects` → `200`。

### 内容平台鉴权前后对比（同一接口 `/api/projects`）

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 无任何身份 | `200`（匿名返回空列表） | `401 UNAUTHORIZED` |
| 伪造 `X-Content-User-Id` | 可被采信 | `401`（中间件入口即剥离） |
| 有会话无映射 | — | `403 IDENTITY_NOT_MAPPED` |
| 有映射只读账号写 | — | `403 FORBIDDEN` |

### 跨境鉴权前后对比

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 无 token | 路由未鉴权 | `401` |
| `demo-access-token` | 有效身份 | `401`（不再是身份来源） |
| 有会话无组织映射 | — | `403 商家组织关联未启用` |
| 有会话有映射 | — | `200` |

## 三、验收中发现并已定位的环境缺陷（非本轮代码缺陷）

### D-01 跨境预览库未跑迁移（阻塞统一登录可用）

`backend/data/ops_workbench.db` 的 `alembic_version` 实测为 **`20261015_0017`**：
- 缺 `merchant_organization_mappings` / `merchant_shop_grants` / `merchant_access_audit` 三张表
- `products` 缺 `external_id` / `hub_product_id` 两列
- 表数 35（head 应为 37）

后果：带合法 token 访问跨境接口 → `500 no such table: merchant_organization_mappings`。

调度者已在**临时副本**上验证修复路径：`alembic upgrade head` 成功 → 500 消失 → 建映射后 `200`。
**未对业务库执行**（需用户确认后单独进行）。

### D-02 `shop-web`(8080) 启动后静默退出

工作台 `/status` 长期报 `shop:failed`。日志显示编译成功（`DONE Compiled successfully`、`App running at http://127.0.0.1:8080/admin/`）后进程消失，无错误行。属既有运行时问题，与本轮后端任务无关，未修。

### D-03 端口 8000 存在两个跨境 API 进程

`pid 4172`（uv python 3.13）与 `pid 10788`（项目 `.venv`）同时监听 8000，属既有异常。当前运行的是**旧代码**，本轮跨境改动需重启才生效。
