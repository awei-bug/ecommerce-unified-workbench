## 四、本轮修复：权限提示文案误导

**现象**：内容平台「商品批量内容」页在已登录状态下显示「未检测到云购商家会话，请先登录商家后台」。

**根因**：`forbiddenHint(action, roleCode)` 只凭 `roleCode` 判断。清空项目数据后 `roleCode` 必为空 → 误判为「未登录」。

**修复**：
- `buildPermissionView` 新增 `authenticated` 字段（由 token 是否存在决定）
- `forbiddenHint(action, roleCode, authenticated)` 三态区分：
  - 有角色但只读 → 「当前角色（xx）为只读，无法编辑」
  - **已登录无项目** → 「已登录商家账号，但尚未加入任何项目；请先由项目管理员把你加入项目成员」
  - 未登录 → 「未检测到云购商家会话…」（原文案，此时才是对的）

**验证**：页面实测显示新文案；50 项测试全过；构建通过。

## 五、疑案破解：「偶发 401」不是代码 bug

多轮验证中「有时正常有时 401」的真正原因：

1. 云购登出/重启会**吊销旧 token**（`t_revoked_tokens` 机制 + 服务重启）
2. 浏览器里的统一会话 Cookie 随之失效，但**页面标签页没有重新登录**
3. 内容平台的批量类接口**每次实时回源云购校验** → 正确 401
4. 而 `/api/auth/me` 在 token 为空时的行为与实时校验不同，造成「me 是 200、其它是 401」的假象

**排查过程中走过的弯路**（记录避免重复）：
- 先怀疑 vite 缓存 → 重启后仍复现
- 再怀疑 React 竞态 → 修了两处真实竞态（有价值的改动，但不是本次 401 的原因）
- 最后在页面里直接调云购 `/user/me/`，看到 `body.status=401「token 无效或已过期」`，再查 `localStorage.getItem(...)` 长度为 **0**——真相是**根本没登录**

**正确流程**：清数据/重启云购后，浏览器必须**重新走一次登录**。

### 对订单数据做了移除实验（已还原）

把 `ORDER_ROWS` 置空后跑完整测试，**4 项测试失败**：


**结论**：这批订单不是孤立的"填充数据"，而是被 5 处代码共同依赖的演示基线：

| 消费方 | 用途 |
|---|---|
| `order_repository.py` | 订单列表、详情、批量处置 |
| `automation_repository.py` | 自动化规则命中订单 |
| `diagnosis_engine.py` | 经营诊断 |
| `diagnostics_service.py` | 诊断报告 |
| `tests/test_api.py` | 4 项接口测试 |

**移除会连带影响**：订单页、自动化、诊断、报表四个模块变空，且要重写 4 项测试。

3. **直接清空并改测试**——最快，但四个模块会失去演示能力
